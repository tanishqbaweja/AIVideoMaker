# V-GEN Project Comprehensive Walkthrough

This document serves as the complete, definitive guide to the V-GEN AI Video Maker architecture. It details every step of the generative pipeline, the specific intricacies of how audio and video are synchronized, how APIs are managed, and how the final video is assembled.

## Overview
V-GEN is a Next.js (React) application with a Node.js backend that orchestrates multiple APIs (Gemini, Groq, Pexels) and local binaries (WhisperX, FFmpeg) to automatically generate highly-retaining, fast-paced YouTube Shorts or 16:9 videos. It is fully automated via a Python orchestrator to select topics, generate videos, upload to YouTube with CTR-optimized metadata, and send Discord notifications upon completion.

---

## The Frontend UI (`app/page.tsx`)
The user interface provides two paths for generation:
1. **Custom Prompt & Vibe**: The user inputs a free-form topic (e.g., "The History of Rome") and a narrative vibe (e.g., "Epic and Fast-Paced").
2. **Quick Topics**: A dropdown containing 10 hardcoded, highly-optimized topic presets (e.g., "Obscure Facts Engine", "Creepy Knowledge"). Selecting one of these overrides the custom prompt/vibe fields.

The UI tracks the generation job via long-polling (`/api/generate/[jobId]`) and displays the real-time status of 5 distinct pipeline steps, updating visually as the backend processes the video.

## The Core Pipeline (`lib/engine.ts`)
When a job is submitted, `runGenerationJob` executes the 7-step pipeline.

### Step 1: Gemini Scripting (`lib/gemini.ts`)
The foundation of the video is the script generated by Gemini (`gemini-3-flash-preview`).

*   **Prompt Engineering**: 
    *   If a **Quick Topic** is used, the system injects a random "sub-angle" (e.g., "from the last 10 years") to ensure varied generations even if the same topic is selected twice.
    *   **Anti-Repetition (Fact History)**: If a topic has been used before, the system reads `fact_history/[topicId].json` and feeds the past 10 scripts back into the prompt, explicitly instructing Gemini *not* to reuse any of those facts.
*   **Strict Constraints**: Gemini is commanded to output a video script spanning exactly **40 to 45 seconds** and containing exactly **120 to 150 words**. 
*   **Pexels Search Restrictions**: Gemini is forced to output a maximum of **1 to 2 words** for the Pexels `searchQuery` (focusing only on the primary noun). This bypasses the Pexels API's "tag dilution" issue, where overly descriptive queries like "wombat walking in nature" return videos of humans walking in nature rather than wombats.
*   **Subscribe Hook**: The script is forced to end with the phrase `"Make sure to Subscribe!"`
*   **Failover & Overload**: The API call is wrapped in a failover mechanism that rotates through backup keys (`GEMINI_API_KEY_1`, `_2`, etc.) if rate-limited (HTTP 429). If Gemini is overloaded (HTTP 503), the engine waits 30 seconds and retries up to 5 times.

### Step 2: Gemini TTS Generation (`lib/gemini.ts`)
The full, concatenated script is passed to Gemini's TTS model (`gemini-3.1-flash-tts-preview`).
*   The prompt includes a "Director's note" to enforce a fast, energetic pacing with no dead air.
*   It generates a single, continuous audio track for the entire script. This ensures consistent vocal cadence and prevents abrupt tonal shifts between scenes.
*   FFmpeg rejects internal silence longer than 2.5 seconds and regenerates only the TTS, up to three attempts.

### Step 3: Groq Transcription & WhisperX Alignment
To synchronize video and subtitles to the audio, the engine needs precise timestamps for every spoken word. This is a two-part process.

1.  **Groq Whisper (`lib/groq.ts`)**: The TTS audio is sent to Groq (`whisper-large-v3-turbo`) to get a rapid, rough transcription.
2.  **Sanitization**: Groq's output is cross-referenced with the original Gemini script. Any spelling mistakes or hallucinations introduced by the Whisper model are corrected back to the script's exact text.
3.  **WhisperX (`lib/whisperx.ts`)**: The corrected transcript and natural-speed TTS audio are processed locally via a Python WhisperX subprocess. Only genuine direct, chunked, or slowed forced alignment is accepted; synthetic timing fallback is prohibited.
4.  **Validation and Tempo Mapping**: Complete normalized script coverage is required. Once alignment succeeds, FFmpeg applies the dynamic tempo needed for the 40-45 second target and scales every timestamp using the measured raw-to-processed duration ratio.

### Step 4: Pexels Video Retrieval (`lib/pexels.ts`)
For each scene defined by Gemini, the engine fetches stock footage.

*   **Scoring & Ranking**: The Pexels results are scored based on resolution (total pixels), framerate, and quality tags (HD/UHD).
*   **No Orientation Filtering**: The orientation filter is bypassed. 16:9 videos can be used for 9:16 Shorts (and vice versa) because FFmpeg will later scale them to fill the screen. This drastically increases the pool of high-quality clips available.
*   **Unique Guarantee**: A global `usedVideoIds` Set tracks every downloaded clip. If a clip has already been used in the video, it is skipped, guaranteeing visual variety.

### Step 5: FFmpeg Assembly & Subtitling (`lib/ffmpeg.ts`)
This is where the raw assets are compiled into the final 60fps MP4.

*   **Audio Pacing Correction**: WhisperX aligns the untouched narration first. FFmpeg then applies `atempo`, measures the processed duration, and scales word timestamps by the actual tempo ratio before deriving scene durations.
*   **ASS "Pop" Subtitles (`scripts/generate_ass.py`)**: 
    *   Instead of basic FFmpeg text rendering, a Python script builds an Advanced SubStation Alpha (`.ass`) file.
    *   Every single word is animated with an ASS transform tag (`\t`) to create a spring/bounce pop effect: starting at 0% scale, springing to 130% in 60ms, and settling at 100% in the next 60ms.
    *   The subtitles have zero-gap continuity (Word A ends exactly when Word B begins).
    *   If there is a natural pause in the narration (>0.5 seconds), the subtitle smoothly scales down to 0% over 100ms rather than vanishing abruptly.
*   **Compositing**:
    1.  The Pexels clips are concatenated and scaled to the target resolution (`1080x1920` or `1920x1080`).
    2.  The ASS subtitles are burned directly into the video frames.
    3.  A background music track (`music.mp3`) is dynamically mixed into the audio, ducked to a low volume (`0.06`).
    4.  **Subscribe Overlay**: In the final 3 seconds of the video, a local `sub.mp4` asset is overlaid. FFmpeg applies a chroma-key filter to remove its green background (`#25ff0e`) and scales it to 130% of the video's width, positioning it dynamically above the subtitles.

### Step 6: Fact History Logging
After the final video is successfully saved to the `Final_Video/` folder, the engine checks if a Quick Topic was used.
*   If so, the full text of the generated script is appended to `fact_history/[topicId].json`.
*   This file acts as a circular buffer limited to 10 entries. When the 11th video is generated, the oldest fact in the buffer is deleted. This feeds into Step 1 to guarantee eternal content freshness.

### Step 7: Automation, Upload, and Notification (`scripts/automate.py`)
The pipeline is designed to be completely hands-off. A master Python orchestrator script (`scripts/automate.py`) is triggered by the Windows Task Scheduler twice a day.

1.  **Topic Selection**: The script randomly selects one of the 10 Quick Topics.
2.  **Dev Server Management**: It checks if the Next.js dev server is running. If not, it spawns it as a subprocess and polls (`/`) for up to 90 seconds until ready.
3.  **Job Submission**: It submits a POST request to `/api/generate` with the chosen topic and a `9:16` aspect ratio, then polls the status until completion.
4.  **Metadata Extraction**: When the video is rendered, it extracts the CTR-optimized `youtubeTitle` and `youtubeDescription` that Gemini generated during Step 1. The script ensures `#shorts` is present in both.
5.  **YouTube Upload (`upload.py`)**: The script calls `upload.py`, passing the final MP4, title, description, and the topic's specific tag file (e.g., `tags/obscure_facts_engine.txt`). `upload.py` authenticates via a local `token.json` (OAuth2), uploads the video as unlisted, and prints the final YouTube Video ID to stdout.
6.  **Conditional Publish (`publish.bat`)**: After the upload record is saved, the orchestrator runs the project-local publish BAT when `VGEN_RUN_PUBLISH_AFTER_UPLOAD` is true or unset. Setting it to false leaves the upload unlisted. Publishing inherits hidden VBS execution or visible BAT execution.
7.  **Discord Notification (`scripts/notify_discord.py`)**: Once upload and optional publishing succeed, the Python orchestrator sends the project name, title, topic, and final YouTube link through the existing Discord bot.
8.  **Cleanup**: The orchestrator shuts down the Next.js dev server if it started it.
